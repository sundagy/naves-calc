# ТЗ: параметрический МКЭ-стенд для расчёта автомобильного навеса

Нужно создать локальное Python-приложение для параметрического расчёта
металлического автомобильного навеса методом конечных элементов.

Приложение предназначено для исследования разных конструктивных схем,
а не для выдачи официального проекта или заключения экспертизы.

Главная задача:
я должен иметь возможность менять:

- количество несущих ферм;
- количество рядов ферм;
- направление ферм;
- высоту каждой группы ферм;
- тип фермы;
- размеры профильных труб;
- толщину стенки;
- структуру решётки;
- количество панелей;
- положение опор;
- размеры навеса;
- снеговую нагрузку;
- постоянную нагрузку;
- сталь;
- стоимость металла;

и после нажатия "Рассчитать" видеть:

1. 3D-модель;
2. деформированную модель;
3. усилия во всех стержнях;
4. прогибы;
5. реакции всех опор;
6. наиболее нагруженные элементы;
7. коэффициенты использования элементов;
8. массу металла;
9. ориентировочную стоимость;
10. сравнение нескольких вариантов конструкции.

3. ИСХОДНАЯ ГЕОМЕТРИЯ НАВЕСА — ВАЖНО
==================================================

Навес НЕ прямоугольный.

Форма навеса в горизонтальной проекции —
ТРАПЕЦИЕВИДНЫЙ ЧЕТЫРЁХУГОЛЬНИК.

Запрещено в расчёте, генерации сетки и визуализации
заменять его прямоугольником 12×10 м или 12×7 м.

Система координат:

X — ширина навеса, 0...12 м
Y — глубина навеса
Z — вертикальная координата

Контур:

A = (0,  0)
B = (12, 0)
C = (12, 7)
D = (0, 10)

То есть:

AB = 12 м — передняя сторона;
AD = 10 м — левая сторона;
BC = 7 м — правая сторона;
DC — наклонная задняя сторона.

Задняя сторона в плане НЕ параллельна передней.

Глубина в произвольной координате X:

    depth(x) = 10 - 0.25*x

Контрольные значения:

depth(0)  = 10 м
depth(4)  = 9 м
depth(8)  = 8 м
depth(12) = 7 м

Площадь горизонтальной проекции:

    A = 12 * (10 + 7) / 2
      = 102 м²

Все:

- фермы;
- узлы;
- кровля;
- грузовые площади;
- снеговая нагрузка;
- прогоны;
- опоры

должны строиться именно внутри этого
трапециевидного контура.


==================================================
4. ПАРАМЕТРИЧЕСКАЯ СЕТКА
==================================================

Конструкция состоит из двух возможных направлений ферм.

Группа A — "нижние", основные фермы.

Они проходят приблизительно в направлении Y.

При N нижних фермах их координаты X должны либо задаваться вручную,
либо автоматически равномерно распределяться:

    x_i = width * i / (N - 1)

Каждая ферма проходит от:

    (x_i, 0)

до:

    (x_i, depth(x_i))


Группа B — "верхние" поперечные фермы.

Они проходят поперёк нижних ферм.

Для их положения использовать нормированную координату:

    t = 0...1

где:

t = 0 — передний край;
t = 1 — задний край.

Для каждого t_j линия верхней фермы проходит:

слева:
    (0, 10*t_j)

справа:
    (12, 7*t_j)

В произвольном X:

    y(x) = t_j * depth(x)

Таким образом пересечение верхней и нижней фермы:

    P(i,j) =
    (
        x_i,
        t_j * depth(x_i)
    )

Это должно гарантировать точное совпадение узлов двух систем.

--------------------------------------------------
7.1. КООРДИНАТЫ СТОЛБОВ
--------------------------------------------------

Система координат:

X — ширина навеса, 0...12 м
Y — глубина навеса
Z — вертикаль

Передняя сторона навеса:

C1 = (0,  0)
C2 = (4,  0)
C3 = (8,  0)
C4 = (12, 0)

Задняя наклонная сторона:

C5 = (0,  10)
C6 = (4,  9)
C7 = (8,  8)
C8 = (12, 7)

Дополнительные боковые опоры:

C9  = (0,  3.5)
C10 = (12, 3.5)

Итого:

    10 столбов.

Каждый столб является отдельным вертикальным расчётным элементом:

    (x, y, z_ground)
        →
    (x, y, z_support)

Столбы должны быть отчётливо видны как отдельные элементы
и в МКЭ-модели, и в 3D-визуализации.

Столбы обозначать:

    C1 ... C10

--------------------------------------------------
7.3. МКЭ-СОЕДИНЕНИЕ СТОЛБА И ФЕРМЫ
--------------------------------------------------

Каждая точка опирания нижней фермы на столб должна быть
РЕАЛЬНЫМ общим узлом МКЭ.

Запрещено:

- только визуально пересекать ферму и столб;
- создавать два независимых узла с одинаковыми координатами;
- считать соединёнными элементы только потому,
  что они геометрически совпадают;
- передавать реакцию в середину стержня без создания узла.

В месте каждого столба должен существовать общий расчётный узел,
к которому одновременно подключены:

- верхняя точка соответствующего столба;
- пояс нижней фермы;
- при необходимости элементы решётки.


Например, для C9 обязательно должен существовать общий узел:

    (0, 3.5, z_support)

к которому подключены:

    C9
    F1


Для C10 аналогично:

    (12, 3.5, z_support)

к которому подключены:

    C10
    F4


Если положение промежуточного столба не совпадает
с существующим узлом панели фермы, генератор фермы обязан:

1. создать узел точно над столбом;
2. разделить пояс фермы в этом месте;
3. корректно перестроить соседнюю решётку;
4. обеспечить непрерывную передачу нагрузки.


--------------------------------------------------
7.4. ЗАПРЕТ ВНУТРЕННИХ СТОЛБОВ
--------------------------------------------------

По умолчанию:

    allow_interior_columns = False

При этом режиме запрещено создавать любые столбы
внутри парковочного пятна.

Допускаются только столбы на периметре навеса.

Программа должна автоматически проверять это условие.

Если пользователь или генератор пытается создать внутреннюю опору,
расчёт должен быть остановлен с понятным сообщением:

    "Interior columns are disabled for this project."


--------------------------------------------------
7.5. РЕЖИМЫ ОПОР ДЛЯ ПАРАМЕТРИЧЕСКИХ ВАРИАНТОВ
--------------------------------------------------

Поддержать три режима:

1. EXISTING_10

   Использует строго исходные 10 столбов:

   C1 ... C10.

   Этот режим обязателен для preset `original`.


2. LOWER_TRUSS_ENDS

   Используется только для новых параметрических вариантов.

   Под концами каждой нижней основной фермы
   автоматически создаются столбы на переднем
   и заднем периметре.

   Внутренние столбы при этом не создаются.

   При allow_interior_columns=False
   все автоматически создаваемые столбы обязаны лежать
   на границе трапециевидного контура.


3. CUSTOM

   Пользователь вручную задаёт положение столбов.

   Каждая пользовательская опора должна проходить проверку:

   - находится ли она на допустимом месте;
   - соединена ли с расчётной схемой;
   - не находится ли внутри парковочного пятна,
     если allow_interior_columns=False.


--------------------------------------------------
7.6. ГРАНИЧНЫЕ УСЛОВИЯ СТОЛБОВ
--------------------------------------------------

Основание каждого столба должно иметь настраиваемый тип:

    FIXED
    PINNED

По умолчанию:

    FIXED

Тип закрепления должен быть явно показан
в интерфейсе и в отчёте.

Соединение:

    column → lower_truss

также должно иметь настраиваемый тип:

    PINNED
    RIGID

По умолчанию для первоначального анализа использовать
тот тип соединения, который задан в preset/config,
и явно отображать его пользователю.


--------------------------------------------------
7.7. КОНТРОЛЬНЫЕ ПРОВЕРКИ
--------------------------------------------------

Для preset `original` автоматически проверять:

1. Количество столбов:

       == 10


2. Координаты:

       C1  == (0,0)
       C2  == (4,0)
       C3  == (8,0)
       C4  == (12,0)

       C5  == (0,10)
       C6  == (4,9)
       C7  == (8,8)
       C8  == (12,7)

       C9  == (0,3.5)
       C10 == (12,3.5)


3. Ни один столб не находится строго внутри
   парковочного пятна.


4. Каждый верхний узел столба принадлежит
   соответствующей нижней ферме.


5. В местах C9 и C10 нижние фермы F1 и F4
   имеют реальные расчётные узлы.


6. Не существует двух независимых узлов
   с одинаковыми координатами в местах опирания.


7. Для каждого столба существует непрерывный путь передачи нагрузки:

       roof
       →
       upper truss
       →
       lower truss
       →
       column
       →
       support/ground

==================================================
8. ВЫСОТА СТОЕК И ПЛОСКОСТЬ КРОВЛИ
==================================================

Не придумывать фиксированную высоту навеса.

Создать ввод:

- высота переднего левого угла;
- высота переднего правого угла;
- высота заднего левого угла;

по трём точкам определить плоскость кровли:

    z = a*x + b*y + c

Высоту четвёртого угла вычислять автоматически.

Также показывать:

- уклон по X;
- уклон по Y;
- максимальный угол кровли.

Если высоты не введены, приложение может визуализировать
условный горизонтальный навес, но должно показывать предупреждение:

"Высотные отметки кровли не заданы. Расчёт коэффициента формы
снеговой нагрузки требует фактического уклона."

Создать библиотеку прямоугольных и квадратных профильных труб.

Формат:

    RHS(width, height, thickness)

Примеры:

60x40x3
80x40x3
80x40x4
100x50x3
100x50x4
120x60x3
120x60x4

SHS:

20x20x2
30x30x2
40x40x2
40x40x3
50x50x2
50x50x3
60x60x3
80x80x3
100x100x3
100x100x4


Для каждого профиля автоматически вычислять:

A
Ix
Iy
Wx
Wy
радиусы инерции
массу кг/м

Использовать точную геометрию прямоугольной трубы:

A = B*H - (B-2t)*(H-2t)

Ix и Iy вычислять как разность моментов инерции
наружного и внутреннего прямоугольников.

Плотность стали:

    rho = 7850 кг/м³


==================================================
12. МАТЕРИАЛ
==================================================

Создать объект SteelMaterial.

Параметры:

E = 2.0e11 Па
nu = 0.3
G = E/(2*(1+nu))
rho = 7850 кг/м³

Марка стали и расчётное сопротивление должны задаваться отдельно.

Создать preset:

    C245

Но значения сопротивления не смешивать с МКЭ-моделью.

МКЭ должен рассчитывать усилия независимо от проверки по СП.


==================================================
13. ПУТЬ ПЕРЕДАЧИ НАГРУЗКИ
==================================================

Для исходной двухъярусной конструкции путь нагрузки
должен быть строго следующим:

КРОВЛЯ
   ↓
ВЕРХНИЕ ФЕРМЫ
   ↓
НИЖНИЕ ФЕРМЫ F1...F4
   ↓
СТОЛБЫ C1...C10
   ↓
ОПОРЫ / ФУНДАМЕНТЫ

Верхние фермы не имеют собственных стоек.

Они опираются непосредственно на нижние фермы.

Нижние фермы непосредственно опираются на столбы.

Кровельная нагрузка не должна никаким другим путём
передаваться непосредственно на столбы.

Для каждого загруженного узла должна существовать
непрерывная цепочка элементов до закреплённой опоры.


==================================================
14. ЭЛЕМЕНТЫ МКЭ
==================================================

Пояса и решётки идеальной фермы:
    axial/truss elements.

Стойки:

==================================================

где:

Нельзя просто скрыто использовать:

22. ПЕРЕНОС ПЛОЩАДНОЙ НАГРУЗКИ В МКЭ
==================================================

Это критическая часть.

Нельзя просто умножить снег на длину каждой фермы.

Нужно обеспечить сохранение полной нагрузки.

Для верхних ферм определить грузовые полосы.

Для каждой верхней фермы j найти полосу:

между половинами расстояний до соседних ферм.

Площадь каждой грузовой ячейки рассчитывать по
горизонтальной проекции кровли.

Нагрузка ячейки:

    F = q * A_cell

где q — кН/м².

Далее распределить её по соответствующим узлам верхней фермы.

Главное условие:

    sum(all_vertical_snow_forces)
    ==
    snow_pressure * loaded_roof_area

с погрешностью менее 0.1%.

Для равномерного снега на всей кровле:

    loaded_roof_area = 102 м².

Создать автоматический unit-test для этого условия.
