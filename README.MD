# naves-calc

Параметрический МКЭ-стенд для предварительного расчёта металлического автомобильного навеса.

Проект позволяет менять геометрию, сечения, схему опор, нагрузки и стоимость металла, запускать линейный статический расчёт через OpenSeesPy и просматривать результаты в локальном Streamlit-интерфейсе.

> Важно: приложение предназначено для исследовательских и предварительных расчётов. Результаты не являются рабочим проектом, расчётным обоснованием для экспертизы или заменой проверки инженером-конструктором.

## Возможности

- построение параметрической 3D-модели трапециевидного навеса;
- расчёт стержневой модели методом конечных элементов через OpenSeesPy;
- визуализация геометрии, деформированной схемы, усилий, прогибов, реакций и нагрузок;
- проверка осевого использования элементов;
- расчёт массы металла и ориентировочной стоимости;
- сравнение нескольких рассчитанных вариантов;
- экспорт результатов в JSON, CSV, XLSX и HTML-отчёт.

## Геометрия навеса

Навес моделируется как трапециевидный четырёхугольник в плане, а не как прямоугольник.

Координаты контура:

- `A = (0, 0)`
- `B = (12, 0)`
- `C = (12, 7)`
- `D = (0, 10)`

Глубина зависит от координаты `X`:

```text
depth(x) = 10 - 0.25 * x
```

Контрольные значения:

- `depth(0) = 10 м`
- `depth(4) = 9 м`
- `depth(8) = 8 м`
- `depth(12) = 7 м`

Площадь горизонтальной проекции: `102 м²`.

## Установка

Проект рассчитан на запуск через `uv`.

Если `uv` не установлен, установите его:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Затем откройте новый терминал и установите зависимости:

```bash
uv sync
```

```bash
uv run streamlit run app.py
```

Если в текущем checkout уже есть настроенное окружение `.venv`, приложение можно запустить без `uv`:

```bash
.venv/bin/streamlit run app.py
```

После запуска Streamlit откроет локальный веб-интерфейс в браузере.

## Пресеты

Базовые варианты находятся в `config/presets.yaml`.

Доступные пресеты:

- `naves_one` — отдельная предварительная схема по чертежам «Навес 12×7» для `models/NavesOne.dxf`: 5 ферм серии В, 10 ферм серии Ф и 12 стоек (вариант без `K6`);
- `variant_6x10` — 6 нижних ферм и 10 верхних;
- `variant_4_high` — 4 нижние фермы с увеличенной высотой;
- `variant_6_medium` — 6 нижних ферм средней высоты;
- `variant_7_medium` — 7 нижних ферм средней высоты.

Список доступных профильных труб задаётся в `config/sections.yaml`.

### Модель `NavesOne.dxf`

DXF содержит детализированные поверхности и чертёжные линии, а не готовую стержневую схему. Вариант `naves_one` восстановлен по листам 2–5 и 13–15 PDF «Навес 1809»: контур кровли `(0, 0)–(12, 0)–(12, 7,03)–(2,588, 9,659)` м, нижние фермы В глубиной 700 мм (согласованный вариант усиления), верхние фермы Ф трапециевидные, 12 стоек 120×120×3. Только F1 имеет высоты 400 → 170 мм. Все F начинаются с 400 мм со стороны K5; перепад высоты каждой фермы равен `230 × L / 12,725` мм, где `L` — её длина в метрах с левым свесом 725 мм. Верхние пояса лежат в общей плоскости кровли, нижние — в другой общей плоскости; уклон поясов одинаков для всех F. По запросу исключена стойка `K6` в точке `(left_x(2,659); 2,659)` м; стойка `K4-middle-2` сохранена; исходный чертёж содержит 13 стоек. Разбиение фермы В1 в месте исключённой опоры сохранено. Пояса ферм и решётка нижних ферм заданы трубой 60×60×3; решётка верхних ферм — 40×40×3. Все стойки имеют высоту 2700 мм от общей нулевой отметки (`column_height_mm`). Нижние пояса нижних ферм горизонтальны; плоскость кровли рассчитывается по высоте стоек и ферм. Изменение высот ферм в параметрах меняет отметки кровли, сохраняя высоту стоек. Параметры `lower_height_mm`, `upper_height_mm` и `upper_end_height_mm` заданы в пресете `naves_one`. Ограничение `upper_max_diagonal_mm: 500` автоматически сгущает решётку F, сохраняя узлы опирания: длина каждой диагонали между узлами не превышает 500 мм. Высоты F должны быть меньше этого предела.

Трубы 40×20×1,5 из спецификации (251,31 кг) учитываются как распределённый собственный вес без моделирования их жёсткости. Масса идеализированной схемы составляет около 2798 кг против 2859,49 кг по спецификации за вычетом К6 (исходная спецификация — 2882,91 кг); стержневая идеализация решётки отличается от деталировки чертежа. В текущем МКЭ горизонтальные перемещения исходных узлов закреплены, поэтому результаты относятся к вертикальной идеализации, а не к полной пространственной проверке. Расчётные соединения и закрепления оснований на листах не заданы; снеговая и постоянная нагрузки редактируются в интерфейсе.

### Детализация МКЭ

В боковой панели выберите число частей на балочный элемент: 1, 2, 4, 8 или 16 (в интерфейсе по умолчанию 4). Балочные пояса, стойки и перекладины разбиваются без изменения сечений, массы и соединений. Новые внутренние узлы свободны по всем степеням свободы; закрепления исходных узлов сохраняются. Решётка из шарнирных стержней не дробится. Нагрузки от кровли остаются в исходных узлах, собственный вес распределяется по новой сетке. Для программного вызова задайте `CanopyInput.fem_subdivisions` (по умолчанию 1 для совместимости).

Сгущение позволяет подробнее отображать прогибы балок; само по себе оно не устраняет допущения расчётной схемы. Сравнивайте результаты на нескольких сетках. Для сгущённой сетки применяется разреженный решатель OpenSees UmfPack.

### Проверка расчётной схемы (12.10.2026)

Размеры труб задаются как ширина × высота × толщина в миллиметрах. Площадь и моменты инерции вычисляются для полой прямоугольной трубы без скруглений. Для кручения используется приближение тонкостенного замкнутого сечения `J ≈ 4 A_m² t / p_m` по средней линии стенки вместо полярного момента `Ix + Iy` ([SCI P385, приложение B.2.3](https://www.steelconstruction.info/images/6/6f/Sci_p385.pdf)). Это приближение, а не характеристика из сортамента производителя. Нулевые, отрицательные и нечисловые размеры отклоняются.

Ориентация балочных сечений согласована с объёмным видом: ширина вертикальных стоек направлена по X, высота горизонтальных и наклонных балок лежит в вертикальной плоскости их оси. В OpenSees локальная ось z направлена по ширине, y — по высоте; передаются соответствующие `Iy` и `Iz` ([OpenSees Linear Transformation](https://opensees.github.io/OpenSeesDocumentation/user/manual/model/geomTransf/Linear.html)). Проверены аналитические прогибы прямоугольной балки в трёх направлениях в плане и консольной стойки при поперечной нагрузке по X и Y.

Для NavesOne балочными являются оба пояса верхних и нижних ферм, стойки и перекладины. Решётка работает только на осевые усилия. Верхние пояса непрерывны внутри каждой фермы и участвуют в детализации МКЭ. Опирание верхних ферм на нижние выполнено отдельными совпадающими узлами с общей вертикальной координатой перемещения и независимыми поворотами. Для исключения свободного вращения прямого верхнего пояса вокруг своей оси в начале каждой цепочки задана одна фиксация Rx; изгибный поворот Ry свободен. Это относится к верхним поясам NavesOne в плоскостях XZ. Нагрузка кровли остаётся узловой; сгущение не превращает её в распределённую. Параметры `column_joint`, `truss_joint_model`, `truss_type`, `structure_mode` присутствуют во входных данных, но не переключают схему. `base_fixity` действительно меняет закрепление оснований. Связи `bearing_links` связывают только вертикальное перемещение, не передавая жёсткость реального эксцентричного соединения по остальным направлениям. Дополнительные связи 40×20×1,5 учитываются только массой.

До перевода верхних поясов на балочные элементы на пресете с детализацией 4 вне оснований имелось 580 узлов с горизонтальными закреплениями, из них 535 — также с закреплёнными поворотами. Максимальная горизонтальная реакция такой связи — около 52,8 кН; максимальная абсолютная компонента момента — около 1,53 кН·м. Эти величины относятся к предыдущей версии схемы; актуальные реакции следует получать повторным расчётом. Реакции искусственных связей теперь доступны в результатах приложения, HTML и Excel отдельно от реакций оснований. Баланс вертикальной нагрузки сам по себе не подтверждает физическую корректность схемы.

Для перехода к пространственному расчёту необходимы фактические закрепления оснований, жёсткость узлов ферма–стойка и ферма–ферма, расположение и сечения пространственных связей, а также сведения о работе кровли как диска. Простое снятие текущих ограничений без этих данных не определяет реальную расчётную схему. Расчёт остаётся линейным упругим; устойчивость, эффекты второго порядка, местная устойчивость стенок, полная прочность и соединения не проверяются. Осевой показатель дополнен отдельной проверкой нормальных напряжений от N и изгиба.


### Дополнительные проверки снеговой нагрузки

В боковой панели доступны пять отдельных исследовательских загружений NavesOne:
равномерное и снег на каждой из четырёх половин по X/Y. Нагрузка интегрируется
по пересечению грузовых площадей с половиной реального контура. Половины
ограничивающего прямоугольника не обязательно имеют равную площадь.
Это не полный набор нормативных схем СП 20 и не модель снеговых мешков.
Опция «Рассчитать все снеговые сценарии» добавляет таблицу отдельных экстремумов
и отдельный расчёт равномерного нормативного снега при γf=1; это не автоматическая
проверка допустимого относительного прогиба. Собственный вес и постоянная нагрузка
пока имеют коэффициент 1; нормативные сочетания ещё не реализованы.

Для балок извлекаются 12 локальных концевых усилий OpenSees. `elastic_NM_util`
считает максимум `(|N|/A + |My|/Wy + |Mz|/Wx)/Ry` по двум концам КЭ.
Соответствие осей проверено аналитической консолью. При узловых нагрузках
изгибающий момент линеен внутри КЭ. Срез, кручение, местная и общая устойчивость,
пластические резервы и соединения этим показателем не проверяются.
Реакции оснований теперь включают три момента.

`effective_lengths_m` задаёт расчётные длины по полю `label` физического элемента
(оно сохраняется при сгущении сетки). В таблице интерфейса можно указать, например, элемент `K7` и длину `5.4` м.
Длину следует назначать по реальным закреплениям; длина КЭ никогда не подставляется
автоматически. Индикатор Эйлера использует минимальный момент инерции и заданную
длину; значение меньше единицы НЕ означает прохождение проверки устойчивости СП 16.
Без длины результат пустой. Для разных длин в двух плоскостях эта упрощённая
проверка недостаточна.

Диагностика без искусственных закреплений снимает все поступательные опоры вне
оснований и поворотные заделки балок. Неработающие повороты чисто стержневых узлов
закреплены. Вертикальные связи опирания не превращаются в пространственные узлы;
недостающие связи автоматически не добавляются. Отказ решателя означает, что
данная модель не даёт решения; он не доказывает аварийность реального навеса.

Во всех результатах и отчётах есть таблица покрытия проверок и явный статус
«Надёжность не подтверждена». Для завершения требуются реальные схемы связей,
узлы и швы/болты, расчётные длины, основания/анкеры/грунт, эксплуатационные
критерии, нормативные сочетания и расчёт устойчивости с несовершенствами.

### Пространственная модель и мембранная кровля

Актуальный `naves_one` использует `spatial_frame=True`: все стержни, включая
решётку, представлены пространственными упругими балками. Сварные соединения
приняты абсолютно жёсткими как расчётная гипотеза, а не как подтверждённое свойство
фактических швов. Только 12 оснований имеют закрепления. Искусственных опор
и фиксаций поворотов поясов над землёй нет. Это линейный расчёт первого порядка,
не проверка устойчивости и не подтверждение готовности к строительству.

Связи между уровнями задаются `rigidLink('beam', ...)`: передаются все силы и
моменты, а при смещённых осях учитывается кинематика жёсткого рычага
`u_slave = u_master + rotation × offset`. Смещения осей у перекладин сохраняются;
пересечения поясов ферм пока идеализированы совпадающими осями. Узловые цепочки
ограничений и повторные зависимые узлы отклоняются, как требует обработчик
[OpenSees Transformation](https://openseespydoc.readthedocs.io/en/latest/src/TransformationMethod.html).
Кинематика [rigidLink](https://openseespydoc.readthedocs.io/en/latest/src/rigidLink.html)
проверена аналитическим примером стойки с эксцентричной вертикальной нагрузкой.
Баланс включает три силы и три момента с учётом моментов реакций в основаниях.

Решётка остаётся неразбитой на дополнительные КЭ, но в пространственном режиме
работает на изгиб и кручение. Собственный вес по-прежнему сосредоточен в концах
элементов. Ориентация прямоугольных труб соответствует `beam_width_axis`;
для прямоугольных сечений фактическую ориентацию нужно сверить при деталировке.

В интерфейсе можно выбрать старую вертикальную идеализацию или её диагностику
для сравнения. Для программного вызова прежнего режима задайте
`spatial_frame=False`; `spatial_diagnostic=True` отдельно снимает его искусственные
закрепления, сохраняя прежние вертикальные связи опирания.

Кровельная система — мембрана. Уклон около 1,072° сохранён.
Согласованный вариант: нижние фермы 700 мм, их решётка 60×60×3;
верхние фермы 400→170 мм и пояса 60×60×3 сохранены. Относительно
варианта с нижними фермами 500 мм кровля поднята на 200 мм.
При прежних условных нагрузках и жёстких узлах максимум N–M/Ry ≈ 0,84,
Max Uz ≈ −19,85 мм (4 КЭ на балочный элемент). Это частичная проверка,
не подтверждение устойчивости, соединений или готовности к строительству.
`roof_dead_load_kpa` — полный вес мембраны, несущего основания и всех слоёв/крепежа,
без уже учтённого собственного веса металлокаркаса. Значение 0,15 кН/м² сохранено
как условное до выбора основания; `roof_load_confirmed=False`. Мембрана и
основание не добавляют жёсткость или связи в МКЭ. Уклон, водоотвод и основание
кровельной системы требуют отдельного проектирования с учётом прогибов.
Дополнительная масса 251,31 кг из старой спецификации сохранена без жёсткости;
её состав и отсутствие двойного учёта с новой кровлей необходимо уточнить.

### Адресное сравнение сечений

`PYTHONPATH=. .venv/bin/python scripts/compare_local_strengthening.py` сравнивает
текущую модель с заменой верхнего пояса B3 и отдельно B3+B4 на 60×60×4
по пяти снеговым схемам; сохраняет HTML, CSV и отдельные JSON в
`outputs/reports/local-strengthening/`. Основной пресет при этом не меняется.
`CanopyInput.member_section_overrides` задаёт сечение по точной метке всего
пояса/стержня, например `{"B3 top chord": "60x60x4"}`. Замены применяются до
разбиения на КЭ, учитываются в массе и жёсткости. Неизвестные метки и сечения
отклоняются; наружные размеры должны совпадать, чтобы сохранить геометрию узлов.
Это сравнение нормальных напряжений, не проверка устойчивости и сварных узлов.
